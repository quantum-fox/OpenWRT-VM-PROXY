# Параметры виртуальной машины роутера

| Параметр | Значение | Почему |
|---|---|---|
| ОЗУ | 384 МБ (достаточно 256–512) | при ~700 соединениях роутер использует около 130–250 МБ; меньше 256 МБ не рекомендуется |
| vCPU | 2 | Xray обрабатывает соединения параллельно; при 1 vCPU пик нагрузки (300–350 соединений) упирается в одно ядро. Больше числа физических ядер хоста не нужно |
| Сетевые карты | `virtio` | паравиртуальная карта дешевле по ЦП, чем эмуляция Intel e1000; драйвер `virtio_net` в ядре OpenWrt есть |
| Паравиртуализация | `kvm` | гость использует KVM-совместимые часы; меньше накладных расходов |
| Диск | 3 ГБ (динамический VDI) | образ OpenWrt по умолчанию имеет корень ~100 МБ — для PassWall2 мало (см. ниже) |
| Сеть | nic1 = Host-Only (LAN), nic2 = мост на внешний адаптер (WAN) | см. [architecture.md](architecture.md) |

Гостевых дополнений (Guest Additions) для OpenWrt нет: показания «изнутри» (`top`, `/proc/stat`) и «снаружи» (VirtualBox, Диспетчер задач хоста) могут расходиться — VirtualBox не сообщает гостю украденное время. Ориентируйтесь на показания хоста.

Изменить параметры вручную (VM выключена):
```powershell
& "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe" modifyvm OpenWRT --memory 384 --cpus 2 --nictype1 virtio --nictype2 virtio --paravirt-provider kvm
```
Или скриптом (от администратора; сам выключает роутер, проверяет результат и **автоматически откатывается**, если после перезагрузки нет SSH, адреса `br-lan` или интернета на WAN):
```powershell
cd <папка OpenWRT-VM-PROXY>\tools\windows
.\vm-tune.ps1                              # 2 vCPU + virtio + kvm
.\vm-tune.ps1 -Cpus 2 -NicType 82540EM     # только vCPU, сеть не менять
.\vm-tune.ps1 -Rollback                    # вернуть 1 vCPU, e1000, paravirt default
```
Параметры «до» сохраняются в `%ProgramData%\win-gateway\vm-before-*.txt`. Простой ~1–2 мин (у Windows срабатывает fail-open). Проверка в госте: `ssh openwrt 'grep -c ^processor /proc/cpuinfo; ls /sys/bus/virtio/drivers/virtio_net'`.

## Расширение диска (вариант A; в варианте B уже сделано)
**Проблема.** В образе `*-ext4-combined-efi` корень — один ext4-раздел (~100 МБ). Обычный путь «увеличить диск → `parted resizepart` → `resize2fs`» не работает: онлайн-расширение падает с `resize2fs: Invalid argument While trying to add group #1`, потому что в штатном образе **resize-inode несогласован** с резервными блоками дескрипторов. Лечится только офлайн (`e2fsck -f` + `resize2fs` на неподключённом разделе), а корень работающей системы отмонтировать нельзя.

**Решение (автоматизировано: `expand-disk.ps1` → `00-expand-disk.sh`, 3 запуска, 2 перезагрузки, ~5 мин).** Система временно загружается с копии корня на третьем разделе:
1. создаётся временный раздел `sda3` (последний гигабайт диска), на него копируется корень, в GRUB временная запись с корнем `sda3` ставится первой → перезагрузка;
2. на `sda3`-системе раздел `sda2` расширяется до начала `sda3`, `e2fsck`/`resize2fs` офлайн чинят и расширяют ФС, свежие `/etc` и `/root` переносятся на `sda2`, GRUB возвращается к исходному → перезагрузка;
3. `sda3` удаляется, `sda2` получает остаток диска, `resize2fs` онлайн (теперь работает). Итог: корень ~2,9 ГБ.

Если после этапа загрузка не удалась — в окне VM (не headless) за 5 секунд выберите в меню GRUB пункт `OpenWrt` (sda2) стрелками: старые разделы не удаляются до последнего шага. Виртуальный диск **уменьшить нельзя**.
