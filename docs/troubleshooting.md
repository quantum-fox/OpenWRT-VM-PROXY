# Неполадки и подводные камни

Проблемы Windows-шлюза (нет интернета после `gateway-on`, туннели, DNS и т. п.) — в [windows-setup.md](windows-setup.md), раздел 3. Здесь — роутер и установка.

## Установка и первый запуск
| Симптом | Причина / что сделать |
|---|---|
| `vm-create.ps1`/`vm-import.ps1`: «Запустите PowerShell от имени администратора» | создание Host-Only адаптера требует прав администратора |
| `vm-import.ps1`: контрольная сумма не совпала | файл `.ova` повреждён при копировании — скопируйте заново |
| Скрипт выбрал не тот WAN-адаптер | задайте вручную: `-WanAdapter "<имя из VBoxManage list bridgedifs>"` (выбирается адаптер с лучшей метрикой маршрута по умолчанию) |
| Роутер не отвечает на `10.99.77.1` | VM запущена? В окне VM (`VBoxManage startvm OpenWRT --type gui`) выполните `ip -4 a`: у `br-lan` должен быть `10.99.77.1`; на Windows у адаптера Host-Only должен быть `10.99.77.2` (`ipconfig`) |
| `ssh openwrt pw2-setup status`: `pw2-setup: not found` | на роутере нет скриптов (роутер собран вручную или старой версией): выполните на Windows `install-router.ps1` (загрузит скрипты в `/usr/share/pw2` и поставит команду `pw2-setup`), затем повторите |
| `pw2-setup apply`: «нет файла /root/secrets.env» | файл с вашими данными отсутствует: выполните `ssh -t openwrt pw2-setup` (без параметров) — он спросит подписку и сервер и создаст файл |
| `router-ssh-setup.ps1`: код 255 / «REMOTE HOST IDENTIFICATION HAS CHANGED» | после переустановки VM у роутера новый ключ: `ssh-keygen -R 10.99.77.1`, затем повторите |
| `router-ssh-setup.ps1`: не удаётся войти по паролю | неверный пароль root (в образе по умолчанию `pw2-change-me`, при варианте A — тот, что вы задали в консоли VM) |
| `pw2-setup`: «подписка дала N узлов (нужно не менее 5)» | неверный адрес подписки либо подписка отдаёт формат, который PassWall2 не разбирает; проверьте на роутере: `curl -s -m 20 -o /tmp/sub.txt '<адрес>'`, затем `head -c 300 /tmp/sub.txt`; заглушки при этом остаются |
| `pw2-setup`: «ссылка … не распознана» | `LINK_WORK` должна начинаться с `vless://` и быть целой, одной строкой |
| Порт 1081 открыт, но данные не идут (соединение «висит») | в ссылке Reality нет `flow=xtls-rprx-vision` при том, что сервер его требует: handshake проходит, данные — нет. Допишите в `LINK_WORK` и выполните `pw2-setup apply` |
| 1081 показывает IP **запасного** узла вместо вашего сервера | ваш сервер недоступен через пул либо ссылка неверна: `pw2-usa-mode status`; `tail /tmp/log/passwall2.log` |
| В `pw2-routing-apply`: «нет узла по шаблону USA — запасной USA не настроен» | в подписке нет узла с `USA` в имени; задайте `USA_BACKUP_MATCH` (см. [routing-rules.md](routing-rules.md)) или игнорируйте (будет только основной выход) |

## Роутер не пингует серверы / нет интернета, хотя на Windows всё работает
Проверяйте по порядку:
1. **Есть ли у роутера выход в сеть:** `ssh openwrt "ip route | grep default; ip -4 addr show eth1"`. Нет строки `default` или нет адреса на `eth1` — потерян DHCP-адрес WAN (в журнале `logread | grep udhcpc`: `lease lost`, `broadcasting discover` без ответа). Причина: после переподключения Wi-Fi на Windows (особенно мобильная точка доступа) мост VirtualBox «залипает», кадры виртуальной карты не доходят до Wi-Fi (не отвечает даже шлюз точки). Помогает только перезапуск VM: `ssh openwrt poweroff` (сторож запустит её сам через минуту) или `VBoxManage startvm OpenWRT --type headless`. Смена `setlinkstate`/`nic2` «на лету» не помогает. Сторож делает это сам: три минуты без маршрута по умолчанию → перезапуск VM (раз в 15 минут максимум).
2. **Белые списки оператора (мобильная сеть):** оператор пропускает только разрешённые адреса (российские сервисы, часть серверов). Проверка без роутера: `curl.exe --noproxy "*" --interface <адрес Wi-Fi Windows> -s -o NUL -w "%{http_code}" https://1.1.1.1/` — если и Windows напрямую не достаёт (`000`), а `https://yandex.ru/` открывается, фильтр на стороне оператора. ICMP (`ping`) к большинству адресов при этом тоже не проходит.
3. **Почему «программа на Windows пингует, а роутер нет»:** собственный трафик роутера (ping, curl на роутере) идёт **напрямую** по WAN (`localhost_proxy=0`), а программа на Windows, подключённая через шлюз/прокси или TUN-клиент, идёт через узлы пула. Если до адреса напрямую нет пути (оператор), прямой ping с роутера не пройдёт, а через прокси — пройдёт. Проверяйте нужный путь: `curl -x http://10.99.77.1:8080 …` (через пул).
4. **Сравните с Windows напрямую:** `curl.exe --noproxy "*" --interface <адрес Wi-Fi Windows> -s -o NUL -m 4 -w "%{time_connect} rc=%{exitcode}\n" http://<адрес узла>:<порт>/` показывает, достижим ли узел с Windows без роутера. Если результат совпадает с роутером (2026-10-06: те же 4 из 17 узлов), фильтр на стороне оператора, а не у роутера. Программа вроде Throne показывает «пинг» узлов по своему пути (через свои туннели/профили), это не прямой путь.
5. **Реклама пропала вместе с нужным сайтом:** временно `pw2-ads off`; постоянно — `pw2-ads allow <домен>` (если домен в `ADS_DOMAINS`) или оставьте блок выключенным.
6. **MTU:** роутер и так подрезает MSS TCP-соединений (в зоне `wan` включён `mtu_fix`). Уменьшать MTU интерфейсов (например до 1280) без доказательств не нужно: измерить путь можно `ping -M do -s <размер> <адрес>` на роутере к адресу, на который проходит ICMP (если ICMP не проходит, измерение невозможно). Меняйте MTU только если крупные страницы виснут, а мелкие открываются, и после проверки на тестовой копии.

## Реклама: российская база не работает / PassWall2 не запускается после обновления баз
- **`pw2-geosite status` показывает «НЕ подключён»** — `geosite.dat` был перезаписан (обновление пакета `v2ray-geosite` или обновление баз в LuCI). Выполните `pw2-geosite ensure` (вернёт списки и перезапустит PassWall2); сам он это делает раз в 15 минут (cron). Если PassWall2 не стартует с ошибкой про `geosite`/`RU-ADS` - то же самое: `pw2-geosite merge`, затем `/etc/init.d/passwall2 restart`.
- **Вернуться к чистому `geosite.dat`:** `pw2-geosite restore`, затем отключите правило: `ADS_GEOSITE_RU=0` в `/etc/pw2-routing.conf` и `pw2-routing-apply` (иначе правило сошлётся на отсутствующий список; `pw2-routing-apply` пропускает такие списки сам).
- **Как проверить, что список действительно работает**, а не просто «сайт не открылся»: Xray отвечает `503` на любую ошибку соединения, поэтому тест нужно строить на **доступном** домене: добавьте его во временный список (`geosite_TEST.dat`) или в `ADS_DOMAINS`, примените правила и сравните ответ до и после (`curl -x http://127.0.0.1:8080 http://<домен>/` на роутере: `200` до, `503` после).

## Подводные камни OpenWrt/PassWall2 (все встречены на практике)
- **Обычный `dnsmasq` ломает прозрачный режим.** В логе PassWall2: «dnsmasq_acl_default crashed», в консоли «recompile with HAVE_NFTSET». Нужен `dnsmasq-full` (ставит `01-packages.sh`); без него клиенты LAN не резолвят имена («нет интернета»). Проверка: `ssh openwrt "grep -c crashed /tmp/log/passwall2.log; dnsmasq --version | grep nftset"` — должен быть `nftset`; затем `/etc/init.d/passwall2 restart`.
- **Списки `opkg` лежат в tmpfs** и пропадают после перезагрузки: перед `opkg install` всегда `opkg update`, иначе «Unknown package».
- **BusyBox**: нет `comm`, `paste`, `nohup`, `cp -x`, рабочего `sort -o`; `free -m` печатает КБ; `nc -z` не работает. Проверка порта: `curl -s -m 7 -o /dev/null -w '%{time_connect}' http://IP:ПОРТ/` (0 = нет TCP).
- **Dropbear (SSH роутера) без sftp**: `scp` не работает. Файлы на роутер — `ssh openwrt 'cat > /путь' < файл` (так делает `install-router.ps1`).
- **PassWall2 стирает из crontab строки со словом `passwall2`** при перезапуске — поэтому команды называются `pw2-*`.
- **В PassWall2 26.x у SOCKS-инстансов нет логина и пароля** — защита только файрволом (WAN `input=REJECT`, прокси слушают LAN).
- **Проверки из Windows при запущенном TUN-клиенте обманчивы**: TUN принимает TCP локально (в `ping` виден `198.18.x.x`). Проверяйте с роутера.
- **PowerShell 5.1** читает `.ps1` без BOM как ANSI: файлы с кириллицей — UTF-8 **с BOM**.
- **Подписки меняют адреса и ID узлов** — поэтому пул пересобирает `pw2-pool-sync`; при смене формата подписки обновление может сломаться: `cat /root/pw2-pool-sync.log`.
- **Изменение состава пула (`pw2-pool-sync`) и переключение режима Китая** перезапускают PassWall2 → разовый обрыв соединений на ~10 с.

## Какой узел брать первым хопом цепочки (замер)
Первый хоп выбирает балансировщик `pool_chain` по минимальному пингу **до `google.com` через узел**, а не до вашего сервера, поэтому лучший по пингу узел не обязательно лучший путь до сервера. Проверка (3 прогона × 5 запросов, временные порты, рабочие порты не затрагиваются):
```sh
ssh openwrt 'BENCH_NODES="Russia Poland Sweden Germany" sh /usr/share/pw2/pw2-chain-bench'   # ровно 4 подстроки имён узлов вашей подписки; вывод: строки DATA
```
Сравниваются: без цепочки, через конкретные узлы подписки и через текущий пул; смотрите медиану и разброс (первый запрос часто медленнее). Если узел плохо подходит как выход (например, не стартует видео), добавьте его в `EXCLUDE_FROM_PROXY_REGEX` в `/etc/pw2-pool.conf` и выполните `pw2-pool-sync`: он уйдёт из 1080/8080 и системного трафика, но останется первым хопом цепочки, если по замеру это не медленнее других.

## Смена подсети роутера (если `10.99.77.0/24` занята в вашей внешней сети)
1. На роутере (консоль VM): `uci set network.lan.ipaddr='10.77.123.1/24'; uci commit network; /etc/init.d/network restart` (пример; DHCP-пул `dhcp.lan.start/limit` остаётся относительным).
2. Адрес Host-Only адаптера Windows: `VBoxManage hostonlyif ipconfig "<имя адаптера>" --ip 10.77.123.2 --netmask 255.255.255.0`.
3. В `tools\windows\gateway-lib.ps1`: `$script:Gw`, шаблоны `10.99.77.*` (несколько мест) и текст сообщений; в `router-ssh-setup.ps1` (параметр `-Router`), `vscode-proxy.ps1` (`-Proxy`, `$noProxy`), `firefox-proxy.ps1` (`-ProxyHost`); в `~\.ssh\config` — `HostName`.
4. Заново выполните `router-ssh-setup.ps1 -Router 10.77.123.1`.

## Откат и повторная установка
- Выключить прозрачный режим, оставив порты: `ssh openwrt "uci set passwall2.@global[0].enabled=0; uci commit passwall2; /etc/init.d/passwall2 restart"`.
- Переустановить правила: `ssh openwrt pw2-routing-apply`; всё целиком: `ssh openwrt pw2-setup apply`.
- Начать с нуля: удалить VM (`VBoxManage unregistervm OpenWRT --delete`) и повторить установку.
