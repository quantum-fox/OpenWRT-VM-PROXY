# Глава 13. Подключение Windows к роутеру: шлюз, сторож, браузер

Эта глава разбирает документ [windows-setup.md](windows-setup.md). Предварительное условие: роутер собран (глава 12), и `ssh openwrt pw2-setup status` показывает выходы 1080 и 1081. Команды из документа проверены на практике; пояснения «что это» — общие объяснения для новичка.

## 13.1. Что мы получим

Когда всё настроено, компьютер работает так:

| Трафик | Путь | Выход |
|---|---|---|
| **Вся система**: Windows, обновления, обычные браузеры и программы без настроек | шлюз Windows → роутер → прозрачный прокси | узел пула с лучшим пингом; российские и китайские сайты напрямую; украинские блокируются |
| **Рабочий браузер** (отдельный профиль Firefox) | явный SOCKS5 `10.99.77.1:1081` | ваш сервер (запасной — при отказе) |
| **VS Code целиком** | прокси `10.99.77.1:8081` | ваш сервер |
| Любая программа по выбору | `10.99.77.1:8080`/`:1080` (пул) или `:8081`/`:1081` (рабочий) | как у соответствующего порта |
| Сам роутер | напрямую | — |

```
                        ┌──────── обычные программы (шлюз) ──────┐
 [Windows] ──────────────┤                                         ├──► [роутер 10.99.77.1] ──► пул ──► интернет
        │                └── рабочий браузер → порт 1081 ──────────┘                   └──► ваш сервер (USA)
```

Сервисы, закрытые для российских адресов, через пул могут отвечать 403 («регион закрыт»): открывайте их через рабочий порт.

### Что такое «шлюз Windows»

Обычно у компьютера есть **шлюз по умолчанию**: устройство, куда он отправляет всё, что не из локальной сети (3.4). Обычно это ваш домашний роутер. «Шлюз Windows» в нашем проекте — это **режим**, когда компьютер вместо домашнего роутера отправляет весь внешний трафик на **наш** роутер `10.99.77.1`. Это делают две «половинки» маршрута (`0.0.0.0/1` и `128.0.0.0/1`), которые вместе перекрывают всё, но не стирают прежний шлюз (так его легко вернуть). Заодно скрипт ставит DNS на роутер.

Включить: `gateway-on`; выключить: `gateway-off`. Если шлюз выключен, интернет идёт обычным путём, напрямую.

### Что такое «сторож»

**Сторож** — это задание в планировщике Windows (2.12) под названием `OpenWRT-Gateway-Watchdog`. Он запускается при входе в систему и **каждую минуту** проверяет здоровье, а именно: запущена ли VM (если нет — запускает), на месте ли маршруты и DNS шлюза (если шлюз включён — восстанавливает), отвечает ли роутер (если нет — **fail-open**: выключает шлюз, и интернет идёт напрямую), нет ли конфликтующих туннелей, есть ли у роутера выход в сеть (если нет 3 минуты подряд — аккуратно перезапускает VM, не чаще раза в 15 минут). Лог: `C:\ProgramData\win-gateway\watchdog.log`.

*Fail-open* (англ. «открыто при отказе») — принцип «при поломке роутера лучше пустить интернет напрямую, чем оставить без интернета». Обратная политика *fail-closed* («лучше без интернета, чем напрямую», kill-switch) в проекте отключена; как её включить — в `windows-setup.md`, раздел 5.

## 13.2. Шаг 1. Проверка связи

🖥️ **ПК · PowerShell** и 🖥️➜📡
```powershell
Test-Connection 10.99.77.1 -Count 2 -Quiet      # True
ssh openwrt 'pw2-setup status'                  # выходы 1080 и 1081 заданы
```
Если `False` или нет ответа — вернитесь к главе 12 (шаги 2–5) и 4.

## 13.3. Шаг 2 (по желанию). VS Code через рабочий выход

VS Code (редактор кода) может ходить в интернет через рабочий выход: расширения, обновления, терминал.

🖥️ **ПК · PowerShell** в папке `tools\windows`:
```powershell
.\vscode-proxy.ps1 -On
```
Скрипт сначала делает резервную копию `settings.json`, затем прописывает прокси `10.99.77.1:8081`. В VS Code: `Ctrl+Shift+P` → **Developer: Reload Window**. Проверка во встроенном терминале VS Code: `echo $env:HTTPS_PROXY` → `http://10.99.77.1:8081`; `curl.exe -s https://icanhazip.com` → IP вашего сервера. Убрать: `.\vscode-proxy.ps1 -Off` и снова Reload Window.

Что меняется в `%APPDATA%\Code\User\settings.json`: `http.proxy`, `http.proxySupport=override`, `http.noProxy`, `terminal.integrated.env.windows` (переменные прокси), `claudeCode.environmentVariables`. (Если вы не используете расширение Claude Code, последняя запись вам не нужна.)

## 13.4. Шаг 3 (по желанию). Рабочий браузер: профиль Firefox

Идея: **один отдельный профиль** браузера, настроенный на порт 1081, служит «рабочим»; остальные профили остаются обычными. *Профиль* — отдельный «набор настроек, закладок и логинов» браузера.

**Вручную (Firefox):** Настройки → Параметры сети → **Ручная настройка прокси**. «Узел SOCKS» — `10.99.77.1`, порт `1081`, **SOCKS v5**, обязательно галка **«Proxy DNS при использовании SOCKS v5»** (чтобы имена сайтов тоже разрешались через прокси, иначе возможны утечки), «Не использовать прокси для» — `localhost, 127.0.0.1, 10.99.77.1`; остальные поля пустые.

**Скриптом** (профиль должен быть закрыт):
```powershell
.\firefox-proxy.ps1 -ProfileDir "$env:APPDATA\Mozilla\Firefox\Profiles\<имя профиля>" -Port 1081
.\firefox-proxy.ps1 -ProfileDir "…" -Off          # убрать
```
Папку профиля узнайте в Firefox: адрес `about:profiles` → «Корневая папка». Проверка: `https://icanhazip.com` показывает IP вашего сервера.

**Chrome/Edge:** в проекте не проверялось. Общий приём — отдельный ярлык с параметрами `--user-data-dir="%LOCALAPPDATA%\WorkBrowser" --proxy-server="socks5://10.99.77.1:1081"`; результат обязательно проверьте (14.5).

## 13.5. Шаг 4. Закройте конфликтующие туннели

Любые другие **VPN/TUN-клиенты** (Throne, v2rayN в режиме TUN, Clash, Outline, WireGuard, OpenVPN) ставят **свои маршруты** и конфликтуют со шлюзом (3.15, 10.7). Закройте их через «Выход» в трее (не просто крестиком окна). Скрипт `gateway-on` откажется включаться, если найдёт активный туннель (параметр `-Force` проверку отключает; зачем — только если знаете).

Проверка, 🖥️ **ПК · PowerShell**:
```powershell
Get-NetAdapter | Where-Object Status -eq Up | Select Name, InterfaceDescription
Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' | Select ProxyEnable, ProxyServer, AutoConfigURL
```
Первая команда — список включённых сетевых адаптеров: среди них не должно быть туннельных (названия вроде `Wintun`, `TAP`, `TUN`, `WireGuard`). Вторая показывает системный прокси Windows: должно быть `ProxyEnable = 0`.

## 13.6. Шаг 5. Сторож

🖥️ **ПК · PowerShell (админ)**
```powershell
.\install-watchdog-task.ps1
```
Создаётся задача `OpenWRT-Gateway-Watchdog` (от вашего пользователя, с повышенными правами, без окна). Проверить её в **Планировщике заданий** (Пуск → «Планировщик заданий» → «Библиотека планировщика»).

## 13.7. Шаг 6. Включить шлюз

🖥️ **ПК · PowerShell (админ)** или 🖱️ двойной щелчок по `gateway-on.cmd`:
```powershell
.\gateway-on.ps1
```
Скрипт: проверяет роутер, туннели и пересечение подсетей → добавляет два маршрута через `10.99.77.1` → ставит DNS `10.99.77.1` на внешний и Host-Only адаптеры → проверяет интернет. **Если интернета нет — сам выключает шлюз.** Ожидается: `Шлюз включён, интернет проверен.` и внешний IP узла пула. Выключить в любой момент: `.\gateway-off.ps1`.

Маршруты хранятся в оперативной памяти (`ActiveStore`) и пропадают при перезагрузке Windows: сторож возвращает их, когда роутер готов.

## 13.8. Шаг 7. Проверка результата

| № | Проверка (🖥️ PowerShell) | Ожидание |
|---|---|---|
| 1 | `curl.exe --noproxy "*" -s https://icanhazip.com` (в терминале VS Code **обязательно** `--noproxy "*"`) | IP узла пула, **не** вашего сервера |
| 2 | `tracert -d -h 2 1.1.1.1` | первый хоп = `10.99.77.1` |
| 3 | `nslookup example.com` | `Server: 10.99.77.1` |
| 4 | терминал VS Code: `curl.exe -s https://icanhazip.com` | IP вашего сервера |
| 5 | рабочий Firefox: `https://icanhazip.com` | IP вашего сервера |
| 6 | 🖥️➜📡 `ssh openwrt "tail -5 /tmp/log/passwall2.log"` | нет ошибок |

Расшифровка ключа `--noproxy "*"`: «не использовать никакой прокси» — чтобы проверить именно системный путь, а не переменные прокси VS Code. `tracert -d -h 2` — путь до `1.1.1.1` только на два прыжка, без имён (7.5).

## 13.9. Шаг 8. Проверка автозапуска и fail-open (один раз)

1. **Перезагрузите Windows.** Через 2–4 минуты после входа: VM запускается, роутер грузится ~30 с, PassWall2 стартует ~20 с, затем сторож включает шлюз. Первые минуты интернет идёт напрямую. Проверка: `Get-Content C:\ProgramData\win-gateway\watchdog.log -Tail 10` и `Get-NetRoute -NextHop 10.99.77.1 | Select DestinationPrefix`.
2. **Fail-open:** выключите роутер командой `ssh openwrt poweroff`. В течение минуты интернет вернётся напрямую («FAIL-OPEN» в логе), затем сторож запустит VM и снова включит шлюз. Выполните это один раз, чтобы убедиться, что страховка работает.

## 13.10. Если что-то не работает

| Симптом | Что сделать |
|---|---|
| После `gateway-on` нет интернета | `.\gateway-off.ps1`; затем 🖥️➜📡 `ssh openwrt pw2-setup status`, `ssh openwrt "tail -30 /tmp/log/passwall2.log"`, при необходимости `ssh openwrt /etc/init.d/passwall2 restart` |
| `gateway-on` пишет о туннельных адаптерах | закройте названную программу (13.5) |
| `gateway-on` пишет о подсети `10.99.77.x` | внешняя сеть использует ту же подсеть, что роутер: шлюз не включится; смените подсеть (11.2) |
| «выполнение сценариев отключено» | запускайте `.cmd`, либо `powershell -ExecutionPolicy Bypass -File …`, либо `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` (2.8) |
| после включения интернета нет, роутер жив | DNS PassWall2 не работает: 10.1 (`dnsmasq-full`) |
| сайты не открываются по имени | `ipconfig /flushdns`; `nslookup example.com 10.99.77.1`; DNS адаптера должен быть `10.99.77.1` (7.4.2) |
| рабочий Firefox показывает IP пула | в профиле другие настройки прокси: 13.4, закройте Firefox перед `firefox-proxy.ps1` |
| после смены Wi-Fi нет интернета | подождите минуту (сторож вернёт DNS и маршруты); иначе `gateway-off`, затем `gateway-on` |
| нужно запустить другой VPN | **сначала** `gateway-off` (иначе сторож продолжит держать маршруты), потом ваш VPN |

Если ничего не помогло — соберите: `Get-NetRoute -NextHop 10.99.77.1`, `Get-DnsClientServerAddress`, `Get-Content C:\ProgramData\win-gateway\watchdog.log -Tail 20`, `ssh openwrt "tail -50 /tmp/log/passwall2.log"` и опишите проблему (2.17, 7.8).

В окне `pw2-gui` (вкладка «Windows») есть кнопки: включить/выключить шлюз, сторож, остановить и запустить VM ([gui.md](gui.md)).

## 13.11. Полный откат

🖥️ **ПК · PowerShell (админ)**; строка с `ssh openwrt` — 🖥️➜📡:

```powershell
.\gateway-off.ps1                                                             # маршруты, DNS, флаг
Unregister-ScheduledTask -TaskName OpenWRT-Gateway-Watchdog -Confirm:$false   # сторож и автозапуск VM
.\vscode-proxy.ps1 -Off                                                       # VS Code (потом Reload Window)
.\firefox-proxy.ps1 -ProfileDir "<профиль>" -Off
ssh openwrt "uci set passwall2.@global[0].enabled=0; uci commit passwall2; /etc/init.d/passwall2 restart"   # (необязательно) выключить прозрачный режим
```

Если интернет пропал совсем — перезагрузите Windows (маршруты шлюза исчезнут), а DNS сбросьте: `Get-NetAdapter | ForEach-Object { Set-DnsClientServerAddress -InterfaceIndex $_.ifIndex -ResetServerAddresses }`.

## 13.12. Ограничения (что важно знать)

- Сеть роутера `10.99.77.0/24` отдельная (роутер `.1`, Windows `.2`, свой Host-Only адаптер). Если внешняя сеть окажется в той же подсети — шлюз откажется включаться (11.2).
- На рабочем порту блокируются российские и украинские сайты **намеренно**.
- **leastPing меняет узел:** внешний IP обычного трафика меняется со временем; сайты с привязкой сессии к IP могут разлогинивать. Рабочие порты стабильны (один IP).
- **Git в панели Source Control VS Code** запускается вне терминала и идёт через пул; в терминале VS Code — через рабочий выход. Принудительно: `git config --global http.proxy http://10.99.77.1:8081`.
- WSL2, Docker Desktop, мессенджеры без своих настроек идут через шлюз → пул.
- **Сон/гибернация Windows:** VM ставится на паузу и возобновляется; сторож восстанавливает состояние за минуту.
- **Сторож сам запускает VM.** Чтобы остановить VM намеренно: кнопка «Остановить VM и сторожа» (окно `pw2-gui`) либо `vm-pause.cmd` (глава 15), либо `Disable-ScheduledTask OpenWRT-Gateway-Watchdog`, затем `ssh openwrt poweroff`.
- **IPv6** на роутере полностью отключён. На Windows отключите привязку IPv6 на внешнем адаптере и на Host-Only (`Disable-NetAdapterBinding -Name "<имя адаптера>" -ComponentID ms_tcpip6` от администратора), иначе возможны утечки мимо шлюза. Вернуть: `pw2-ipv6 on` и `Enable-NetAdapterBinding …`.
