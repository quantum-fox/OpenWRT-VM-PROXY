# Глава 15. Физический роутер вместо виртуальной машины (на примере Netis NX31)

Глава разбирает документ [hardware-router.md](hardware-router.md). Те же скрипты и настройки работают не только в VM, но и на **настоящем роутере** с OpenWrt 24.10. Проверено на Netis NX31 (процессор MT7981, архитектура aarch64, без USB). Что для этого нужно понимать — и что может пойти не так, — в этой главе.

> **О достоверности.** Раздел 15.3 (прошивка) описывает наш опыт с одной моделью и **не является инструкцией для вашего роутера**: у каждой модели свой порядок. Раздел о роутерах других моделей — только общие принципы.

## 15.1. Когда физический роутер лучше виртуальной машины

| | VM в VirtualBox | Физический роутер |
|---|---|---|
| Нужен ли включённый компьютер | да, всегда | нет, работает сам |
| Wi-Fi для телефонов и ТВ | нужна отдельная точка доступа | может быть встроен в роутер |
| Скорость и нагрузка | зависит от компьютера | зависит от процессора роутера (NX31: 256 МБ памяти и 128 МБ флеш, пул, база рекламы и Xray помещаются свободно) |
| Риск | поломка VM не страшна | при ошибке прошивки можно «окирпичить» роутер |
| Простота | всё под рукой | нужно разобраться с железом |

## 15.2. Что нужно от роутера

- **OpenWrt 24.10 или новее** (список поддерживаемых устройств — на сайте OpenWrt; для каждой модели есть своя страница «Table of Hardware»).
- Достаточно памяти: пул, база рекламы и Xray занимают заметное место.
- **Архитектура и версия определяются сами**: `01-packages.sh` читает файл `/etc/openwrt_release`, и нужные пакеты PassWall2 берутся под вашу архитектуру.
- **Имена портов у каждого роутера свои.** В виртуальной версии это `eth0`/`eth1`; у NX31 — `lan1`–`lan3` и `wan`. Если пользуетесь командами `pw2-lan`/`pw2-wan`, указывайте имена из `ip link` именно на вашем роутере.

## 15.3. Подготовка: прошивка (кратко и осторожно)

Если на роутере стоит заводская прошивка, на него нужно поставить чистую OpenWrt. Это самый опасный этап, поэтому:

1. **Сначала найдите страницу вашей модели** на сайте OpenWrt и прочитайте её целиком. Порядок прошивки у разных моделей разный (где-то достаточно загрузить файл в веб-интерфейс, где-то нужно заменить загрузчик и использовать TFTP).
2. **До прошивки снимите копии всех разделов флеш-памяти** (список — файл `/proc/mtd` на роутере). Особенно важен раздел **`Factory`**: в нём **калибровка Wi-Fi, уникальная для каждого устройства**. Без него Wi-Fi может работать плохо или не работать. В нашем случае копии сняты на отдельный диск, и в проект они не входят.
3. Запишите **заводские адреса и пароли** (как правило, `192.168.1.1`).
4. Прошивайте только файлами **из официального источника** для вашей модели и ревизии.
5. Если нужен TFTP (передача файла на роутер по сети): в Windows брандмауэр по умолчанию может блокировать TFTP-сервер в сети с типом «Общедоступная». В нашем случае именно это и мешало: помогло разрешить программе доступ в брандмауэре (2.14).

Пока вы не прошили и не сохранили копии разделов, **считайте роутер необратимо портящимся при любой ошибке**. Если сомневаетесь — найдите человека с опытом.

## 15.4. Установка скриптов проекта

Условия: на роутере чистая OpenWrt и есть интернет по WAN (кабель от домашнего роутера или провайдера в порт `wan`).

Первая строка — 🐧 **ПК · терминал** (Linux, macOS или Git Bash; на Windows вместо неё `install-router.ps1`); вторая — 🖥️➜📡:

```
sh install-router.sh root@192.168.1.1       # загрузить скрипты (из папки tools/router)
ssh -t root@192.168.1.1 pw2-setup            # спросит пароль root, адрес подписки, ссылку рабочего сервера
```

Первая команда копирует файлы проекта на роутер, вторая запускает мастер установки (как в главе 12, шаг «Ваши данные»). Адрес `192.168.1.1` здесь — заводской адрес чистой OpenWrt; подставьте адрес вашего роутера, если он другой.

**Важный принцип:** на роутер, который вы отдаёте другому человеку, **не переносите свои подписки и серверы**. В `secrets.env` и узлах хранятся ваши данные. Для друга используйте **его** подписку (мы так и делали: вводили только его данные).

## 15.5. Адрес роутера в локальной сети (LAN)

Чистая OpenWrt занимает `192.168.1.1`. В виртуальной версии проекта роутер имеет `10.99.77.1`. Чтобы на физическом роутере всё было так же (и скрипты Windows, и документация совпадали), смените адрес командой `pw2-lan-ip` (она же есть в окне `pw2-gui`).

Порядок (шаги на роутере — 📡; на компьютере — 🖥️):

```sh
pw2-lan-ip status                 # сейчас
pw2-lan-ip set 10.99.77.1         # применится через ~3 с; ждёт подтверждения 3 минуты
```
Затем на компьютере: отключите и подключите кабель (или Wi-Fi), чтобы он получил новый адрес. Потом:
```sh
ssh root@10.99.77.1
pw2-lan-ip keep                   # подтвердить, иначе адрес сам вернётся на старый
```

Вариант `pw2-lan-ip set АДРЕС --now` меняет **без отката**: используйте только если подключены кабелем и уверены. Вручную то же: `uci set network.lan.ipaddr=10.99.77.1; uci commit network; /etc/init.d/network restart`.

**Правила:**

- Подсеть LAN **не должна совпадать с подсетью WAN** (скрипт откажется): иначе роутер не поймёт, куда посылать пакеты (3.3, 11.2).
- Если в сети уже есть другой роутер с `10.99.77.1` (например, виртуальная версия в Proxmox), **не включайте оба в один сегмент** (6.12.6).
- Если у вас в доме или офисе сеть уже `10.99.77.x`, выберите другую подсеть (11.2).

## 15.6. Ноутбук с виртуальным роутером и физический роутер одновременно

Бывает, что на ноутбуке уже есть виртуальный роутер, а вы хотите работать через физический. Если у обоих адрес `10.99.77.1`, два адаптера в одной подсети **ломают выход в интернет**. Два скрипта в папке `tools\windows` решают задачу:

- **`vm-pause.cmd`** — выключает шлюз Windows, отключает сторожа, выключает VM и **выключает адаптер Host-Only 10.99.77.x**;
- **`vm-resume.cmd`** — всё возвращает: включает адаптер, сторожа, VM и шлюз.

То же есть кнопками в окне `pw2-gui`, вкладка «Windows». Скрипты на живой VM пока проверены не полностью (план I14).

## 15.7. Wi-Fi

По умолчанию на чистой OpenWrt **Wi-Fi выключен**. Чтобы включить, на роутере (📡) для каждого радиомодуля:

```sh
uci set wireless.radio0.disabled=0
uci set wireless.radio1.disabled=0
uci set wireless.default_radio0.encryption=psk2
uci set wireless.default_radio0.key='ВАШ_ПАРОЛЬ'
uci commit wireless
wifi reload
```

(Для второго радиомодуля — то же для `default_radio1`; имя сети — параметр `ssid`.) Расшифровка: `radio0`/`radio1` — два радиомодуля (обычно 2,4 и 5 ГГц); `encryption=psk2` — шифрование WPA2 с паролем; `key` — пароль Wi-Fi (не короче 8 символов); `wifi reload` — применить.

**Не оставляйте сеть открытой.** Клиенты Wi-Fi попадают в тот же прозрачный прокси и пользуются **вашей подпиской**: открытая сеть значит, что любой сосед может использовать ваши серверы.

Не публикуйте пароль Wi-Fi в открытых местах; для гостей можно потом сделать отдельную сеть (в проекте не описано).

## 15.8. Проверка после установки

Те же, что для VM (глава 14.4): `pw2-setup status`, выходы 1080 и 1081, сторож и шлюз Windows — если компьютер работает через этот роутер как шлюз. Дополнительно для физического роутера:

- `ip link` — имена портов;
- `wifi status` — состояние Wi-Fi;
- проверьте с телефона через Wi-Fi: открывается ли сайт, показывает ли `icanhazip.com` адрес пула.

## 15.9. Типичные проблемы с физическим роутером

| Симптом | Причина | Что делать |
|---|---|---|
| Нет интернета у роутера (WAN без адреса) | в сети WAN нет DHCP или кабель не в том порту | 6.12.7 |
| После смены адреса роутер «пропал» | компьютер остался в старой подсети | 11.2.2 |
| Wi-Fi не виден | выключен по умолчанию | 15.7 |
| Работает по кабелю, не по Wi-Fi | не задан пароль/шифрование | 15.7 |
| `pw2-lan` не принимает порт | другие имена портов | `ip link` на этом роутере |
| Много устройств, медленно | процессор роутера слабее компьютера | снизить нагрузку: `pw2-exit probe`, закрепить сервер (3.9.1) |

## 15.10. Итог главы

- Физический роутер подходит, когда вы не хотите держать компьютер включённым и нужен встроенный Wi-Fi.
- Прошивка — самый опасный этап: **страница вашей модели**, **копии разделов** (особенно `Factory`), официальные файлы.
- Скрипты проекта на OpenWrt 24.10 ставятся теми же шагами, адрес меняется `pw2-lan-ip`.
- Чужому человеку отдавайте роутер **без ваших подписок и серверов**.
- Wi-Fi включайте с паролем.
