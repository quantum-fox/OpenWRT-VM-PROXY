# Правила маршрутизации RU / UA / CN и запасной выход

Правила задаются в `/etc/pw2-routing.conf` и применяются командой `pw2-routing-apply` (то же делает `pw2-setup`). Схема портов и путей — [architecture.md](architecture.md).

## 1. Итоговая таблица
| Путь | UA | RU | CN | Остальное |
|---|---|---|---|---|
| **1080 / 8080** и **системный трафик** (шлюз Windows) | блок | напрямую | напрямую; если Китай напрямую недоступен — через пул (раздел 3) | через пул |
| **1081 / 8081** (рабочий) | блок | блок | как обычно | через пул → ваш сервер |
| **Любой прямой трафик через роутер или от него** | блок по IP (файрвол `ua_block`) | — | — | — |

«Зоны»:
- **UA:** домены `.ua`, `.укр` и IP Украины (`geoip:ua`).
- **RU:** домены `.ru`, `.su`, `.рф`, `geosite:category-ru` (российские сайты на любых зонах) и IP России (`geoip:ru`).
- **CN:** домены `.cn`, `.中国`, `.中國`, `geosite:cn` (в том числе китайские сайты на `.com`) и IP Китая (`geoip:cn`).
- **ADS (реклама и трекеры):** `geosite:category-ads-all` (готовый список ~800 правил: Google Ads, DoubleClick и др. мировые рекламные сети) и свои домены `ADS_DOMAINS` (по умолчанию российские: `mc.yandex.ru` (Метрика), `an.yandex.ru`, `adfox.ru`, `ad.mail.ru`, `top-fwz1.mail.ru`, `counter.yadro.ru` и т. п. — в мировом списке их нет). **Блок на всех портах (1080/8080, 1081/8081) и в системном трафике.** Клиент получает быстрый отказ (для обычного HTTP — `503`, для HTTPS — обрыв). С версии 1.2.0 добавлена **российская база рекламы** (`ADS_GEOSITE_RU=1`): список `category-ads-all` из проекта `runetfreedom/russia-v2ray-rules-dat` (~149 тыс. доменов; полная база проекта весит ~70 МБ и на роутер не грузится, из неё вырезан только этот список, 3,8 МБ). **Как подключается.** Сам Xray умеет читать внешние базы (`ext:файл.dat:тег`), но **PassWall2 такие записи при сборке конфига пропускает** (в его коде: «Rule currently not support ext:»). Поэтому команда `pw2-geosite` **дописывает** файл списка в конец стандартного `/usr/share/v2ray/geosite.dat` (формат geosite позволяет простое склеивание), и список становится обычным тегом `geosite:ru-ads`. Проверка состояния: `pw2-geosite status`. Если `geosite.dat` перезапишут (обновление пакета, обновление баз в LuCI), списки пропадут; страховка - раз в 15 минут `pw2-geosite ensure` (cron) возвращает их и перезапускает PassWall2. Память: 3 процесса Xray занимают ~49-53 МБ каждый (было ~42), всего доступно ~120 МБ при ОЗУ VM 300 МБ. **Свой список** подключается так же: файл `geosite_<ТЕГ>.dat` (внутри один список с тегом `<ТЕГ>`, например собранный проектом `OpenWRT-VM-PROXY-ads`) положить в `/usr/share/pw2/data/`, выполнить `pw2-geosite merge`, добавить в `/etc/pw2-routing.conf`: `ADS_GEOSITE_EXTRA="geosite:<тег в нижнем регистре>"`, затем `pw2-routing-apply`. Включается/выключается `ADS_BLOCK` в `/etc/pw2-routing.conf` или командой `pw2-ads on|off`. Фильтруется только трафик, проходящий через Xray; домены видны по DNS-запросу и SNI (в прозрачном режиме работает сниффинг), реклама, встроенная в тот же домен, что и основной контент (например, видео-реклама YouTube), так не блокируется.
- **ALI (AliExpress/Alibaba):** `aliexpress.com/.ru/.us`, `aliexpress-media.com` (картинки товаров), `alicdn.com/.net`, `aliyuncs.com`, `aliyun.com`, `mmstat.com` (аналитика), `alibabausercontent.com`, `alibaba.com/.net`, `alipay.com`, `alibabadns.com` (список `ALI_DOMAINS` в `/etc/pw2-routing.conf`). На 1080/8080 и в системном трафике направление задаёт `ALI_ACTION` (по умолчанию **напрямую**; переключается командой `pw2-ali-mode direct|pool`); на 8081/1081 — как обычно (через рабочий выход), а `aliexpress.ru` там блокируется как российский сайт. **`aestatic.net`** (российский CDN AliExpress) лежит в зоне RU и всегда идёт напрямую.
- **Важно про российские сервисы AliExpress.** `aliexpress.ru`, `aliexpress-media.com` (картинки) и `aestatic.net` открываются **только с российского IP**: с зарубежных узлов пула и с серверов в дата-центрах они отвечают ошибкой TLS или зависают (проверено 2026-10-05). Поэтому работают два варианта: напрямую (российская сеть без белых списков) или через **рабочий российский узел**. Если оператор режет прямой доступ (белые списки мобильной сети), а российского узла нет, `aliexpress.ru` не откроется ничем: `aliexpress.com` и `alicdn.com` при этом открываются через пул.
- Зона `.org` и прочие в правилах отсутствуют. Приоритет: UA → ADS → RU → ALI → CN → остальное (блок сильнее «напрямую»).

**Что увидит клиент при блоке:** по HTTPS — обрыв соединения (в прозрачном режиме не сразу, до ~10 с); по обычному HTTP через явный прокси — быстрый отказ; для UA-IP файрвол молча отбрасывает пакеты (таймаут).

## 2. Как это работает
- **Xray.** Маршрутизацией по доменам/IP управляют shunt-узлы PassWall2: `shunt_pool` (1080/8080 и система), `shunt_usa` (1081/8081), `shunt_usa_b` (запасной), при `SYSTEM_MODE=ua_only` ещё `shunt_global`. Правила — секции `rule_ua`, `rule_ads`, `rule_ru`, `rule_ali`, `rule_cn` (порядок = приоритет). `domainStrategy=IPOnDemand`: если по домену правило не сработало, домен резолвится и проверяется по IP-спискам. В прозрачном режиме включён сниффинг `http/tls/quic`, поэтому домены определяются и там.
- **Файрвол `ua_block`.** Отдельная таблица nftables вне `fw4` и PassWall2: цепочка `pre` (prerouting, приоритет −300 — до перенаправления в Xray) и `out`; адреса из UA-наборов отбрасываются. Загружается при старте (`/etc/init.d/ua-block`), раз в неделю обновляется (cron `30 4 * * 0`, `pw2-ua-block`). Списки берутся из `geoip.dat` (пакеты `v2ray-geoip`, `v2ray-geosite`); обновить: `opkg update && opkg upgrade v2ray-geoip v2ray-geosite`, затем `pw2-ua-block` и `/etc/init.d/passwall2 restart`.

## 3. Китай: «напрямую, а если недоступен — через пул»
Служба `cn-watch` (режим `CN_MODE="auto"`):
1. Каждые `CN_CHECK_INTERVAL`=30 с **роутер сам** (напрямую, мимо прокси) открывает 5 китайских сайтов (`CN_PROBES`). Китай «доступен», если не менее `CN_PROBE_MIN`=2 ответили кодом 2xx/3xx за `CN_PROBE_TIMEOUT`=8 с.
2. Недоступен `CN_FAIL_THRESHOLD`=20 проверок подряд (~10 мин) → правило CN на `shunt_pool` меняется на `_default` (китайский трафик идёт через пул). Вернуть «напрямую» — после `CN_OK_THRESHOLD`=60 удач подряд (~30 мин).
3. Пороги намеренно очень консервативны: **каждое переключение перезапускает PassWall2** (~10 с без прокси, обрыв всех соединений; онлайн-видео при этом зависает). Важнее долгая стабильность, чем быстрая реакция. Лог: `/root/pw2-cn-watch.log`.

**Ограничения:** проверка идёт по таймеру и из сети роутера; частично доступные сайты сторож не различает.

Ручное управление (отключает автопереключение, кроме `auto`):
```sh
pw2-cn-mode status | auto | direct | proxy       # на роутере
```
С Windows: `tools\windows\cn-mode.cmd status|auto|direct|proxy`. В LuCI (без скриптов): PassWall 2 → список узлов → `SHUNT pool: …` → у правила `CN: …` выбрать «Прямое соединение» либо «По умолчанию» → Save & Apply (при `CN_MODE=auto` сторож вернёт своё решение).

## 4. Запасной выход для 1081/8081
Основной выход — ваш сервер (`USA-via-pool`). Если он перестаёт работать, порт **автоматически** переключается на узел USA **из подписки** (тоже через пул первого хопа: `default_proxy_tag=pool_chain`, напрямую такой узел бывает недоступен); когда ваш сервер снова работает — возвращается.
- **Механизм:** штатное автопереключение SOCKS-инстанса PassWall2. Каждые `USA_CHECK_INTERVAL`=5 с через порт 1081 делается настоящий запрос (`USA_PROBE_URL`, по умолчанию `https://www.google.com/generate_204`; таймаут `USA_CHECK_TIMEOUT`=3 с, `USA_CHECK_RETRY`=1 повтор). При неудаче проверяется запасной узел, и если он работает — переключается только `sockB`. Режим «восстановление» периодически проверяет основной узел.
- **Время переключения ~22 с.** Быстрее не рекомендуется: при одной-двух потерянных пробах на мобильной сети появятся ложные переключения, а каждое рвёт соединения.
- **Узлы:** основной `shunt_usa`, запасной `shunt_usa_b` (те же правила RU+UA блок). Запасной ищется в группе подписки по шаблону имени: `USA_BACKUP_GROUP`, `USA_BACKUP_MATCH` (regex по имени, по умолчанию `USA`). Если в вашей подписке такого узла нет, `pw2-routing-apply` напишет предупреждение и запасной выход не будет настроен (работает только основной); задайте другой шаблон, например `USA_BACKUP_MATCH="Germany|Netherlands"`. `pw2-pool-sync` держит запасной узел актуальным после каждого обновления подписки.
- **Почему не балансировщик Xray с fallback:** наблюдатель (observatory) PassWall2 следит только за узлами с тегом `blc-…`, а у цепочечного узла «пул → сервер» тег другой; он считался бы «мёртвым» и выбирался бы запасной всегда.
- **Управление:**
```sh
pw2-usa-mode status    # какой выход сейчас: основной/запасной, настройки, последние события
pw2-usa-mode backup    # ВРУЧНУЮ закрепить запасной (автопереключение выключается)
pw2-usa-mode auto      # обычный режим (основной + автоматический запасной)
```
- **Ограничения:** у запасного узла другой IP и провайдер (сервисы с привязкой к IP могут потребовать повторного входа); запасной узел из подписки обычно менее скрытен; при переключении соединения рвутся; если не работают оба узла — порт 1081 не отвечает. Отключить запасной: `USA_BACKUP=0` и `pw2-routing-apply`.

## 5. Как менять (шпаргалка)
Все списки и режимы — в `/etc/pw2-routing.conf`. Применить: `pw2-routing-apply` (пересоздаёт правила и узлы, перезапускает PassWall2 на ~10 с; **перезаписывает ручные правки правил в LuCI**).
```sh
vi /etc/pw2-routing.conf
pw2-routing-apply
```
| Что нужно | Что сделать |
|---|---|
| Добавить домен/зону в «RU», «UA», «CN» | дописать слово в `RU_DOMAINS`, `UA_DOMAINS`, `CN_DOMAINS` (без точки; `xn--p1ai` = `.рф`, `xn--j1amh` = `.укр`); `pw2-routing-apply` |
| Заблокировать конкретный сайт на «чужой» зоне | дописать его в `UA_DOMAINS` (например `example.net`) |
| Отключить/изменить гео-списки | `RU_GEOSITE`, `RU_GEOIP`, `UA_GEOIP`, `CN_GEOSITE`, `CN_GEOIP` (пусто = не использовать) |
| Исключить диапазон из файрвол-блока UA (гео-база помечает и CDN-диапазоны) | создать `/etc/ua-block.exclude` с регулярным выражением (egrep) на строку, например `^2\.19\.` (по одной строке на диапазон), затем `pw2-ua-block` |
| Китай «всегда напрямую / через пул / авто» | `pw2-cn-mode direct`, `pw2-cn-mode proxy`, `pw2-cn-mode auto` |
| Направить AliExpress/Alibaba напрямую / через пул / через конкретный узел | `pw2-ali-mode direct`, `pw2-ali-mode pool`, `pw2-ali-mode node <ID узла>` (меняет `ALI_ACTION`); `pw2-ali-mode status` — текущий режим |
| Реклама: включить / выключить / посмотреть / разблокировать свой домен | `pw2-ads on`, `pw2-ads off`, `pw2-ads status`, `pw2-ads allow <домен>` (убирает домен из `ADS_DOMAINS`; если домен блокирует сам список geosite — выключите блок `pw2-ads off` или уберите `ADS_GEOSITE`) |
| Добавить свои рекламные домены | дописать в `ADS_DOMAINS` (слова через пробел), `pw2-routing-apply` |
| Добавить/убрать домены AliExpress/Alibaba (правило ALI) | `ALI_DOMAINS` (слова через пробел, без точки в начале; пустое значение отключает правило); `pw2-routing-apply` |
| Другие сайты-пробы Китая | `CN_PROBES`, `CN_PROBE_MIN`; затем `/etc/init.d/cn-watch restart` |
| Реакция сторожа Китая быстрее/медленнее | `CN_CHECK_INTERVAL`, `CN_FAIL_THRESHOLD`, `CN_OK_THRESHOLD`; затем `/etc/init.d/cn-watch restart` |
| Системный трафик только с блоком UA | `SYSTEM_MODE="ua_only"`; `pw2-routing-apply` (вернуть: `"same"`) |
| Отключить файрвол-блок UA | `/etc/init.d/ua-block stop; /etc/init.d/ua-block disable` |
| Отключить сторож Китая (оставить напрямую) | `pw2-cn-mode direct; /etc/init.d/cn-watch stop; /etc/init.d/cn-watch disable` |
| Выключить запасной рабочий выход | `USA_BACKUP=0`; `pw2-routing-apply` |
| Сменить, какой узел подписки — запасной | `USA_BACKUP_GROUP`, `USA_BACKUP_MATCH`; `pw2-routing-apply` |
| Чувствительность проверки рабочего выхода | `USA_CHECK_INTERVAL`, `USA_CHECK_TIMEOUT`, `USA_CHECK_RETRY`, `USA_PROBE_URL`; `pw2-routing-apply` |
| Откат всех правил к «простым» узлам | `uci set passwall2.sockA.node=pool_ping; uci set passwall2.@global[0].node=pool_ping; uci commit passwall2; /etc/init.d/passwall2 restart` (sockB — на узел `USA-via-pool`) |
| Посмотреть, куда ушёл запрос (системный путь) | `tail -30 /tmp/etc/passwall2/acl/acl_default.log` (`-> direct`, `-> blackhole`, `-> blc-…` = пул) |

В LuCI: `http://10.99.77.1/cgi-bin/luci/admin/services/passwall2` → список узлов (группа `own`), правила (`UA: …`, `RU: …`, `CN: …`), **Socks Config** (узел каждого порта), Basic Settings → Node (узел системного трафика).

## 6. Ограничения и нюансы
- **Сайты с антиботом и «разными путями».** Крупные магазины (например AliExpress) собирают страницу из десятков доменов (страница, картинки, API, аналитика). Если часть доменов ушла напрямую, а часть — через прокси, запросы приходят с разных IP, антибот сайта это замечает: страницы зависают на «загрузке» или просят капчу. Для таких сайтов заведите отдельное правило-список (как `ALI_DOMAINS`), чтобы **всё семейство** шло одним путём. Как найти недостающие домены: когда страница «зависает на загрузке», в панели «Сеть» браузера (DevTools) видно адрес, на котором она ждёт — добавьте его домен в список. Также на роутере: `tail -n 6000 /tmp/etc/passwall2/acl/acl_default.log | grep "tcp_redir -> default"` показывает адреса, которые сейчас идут через пул (кандидаты); `geoview -type geosite -input /usr/share/v2ray/geosite.dat -action lookup -value <домен>` — см. ниже. `geoview -type geosite -input /usr/share/v2ray/geosite.dat -action lookup -value <домен>` на роутере показывает, в каких списках домен есть (если пусто — домен идёт «как остальное», через пул); журнал `/tmp/etc/passwall2/acl/acl_default.log` показывает путь каждого соединения (`direct`, `default`, `blc-…`).
- **Гео-базы неточны:** в `geoip:ua` попадают и CDN-диапазоны; файрвол блокирует их целиком — при жалобах используйте `/etc/ua-block.exclude`.
- **Windows без шлюза** (выключен или fail-open): трафик идёт мимо роутера, правила не действуют.
- Блок по доменам делает Xray, по IP — Xray и файрвол. Явные прокси защищены Xray; файрвол ловит остальное.
- **Проверка системного пути в терминале VS Code** — только с `--noproxy "*"` (подробности — [commands.md](commands.md)).

Проверки:
```powershell
curl.exe -s -x socks5h://10.99.77.1:1080 https://icanhazip.com                          # IP узла пула
curl.exe -s -o NUL -w "%{http_code}" -x socks5h://10.99.77.1:1080 https://yandex.ru/    # 302 (RU напрямую)
curl.exe -s -o NUL -w "%{http_code}" -x socks5h://10.99.77.1:1080 https://kyivstar.ua/  # 000 (UA блок)
curl.exe -s -x socks5h://10.99.77.1:1081 https://icanhazip.com                          # IP вашего сервера
curl.exe -s -o NUL -w "%{http_code}" -x socks5h://10.99.77.1:1081 https://yandex.ru/    # 000 (RU на рабочем блок)
curl.exe --noproxy "*" -s https://icanhazip.com                                         # системный путь (шлюз включён): IP пула
```
```sh
nft list chain inet ua_block pre | grep -E 'daddr|saddr'    # счётчики сброшенных UA-пакетов
```
