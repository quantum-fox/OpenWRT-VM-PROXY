# Как это устроено

## 1. Схема
```
Windows / браузер / программа
   │   (а) явный прокси  10.99.77.1:1080 (SOCKS5) / :8080 (HTTP)   — общий
   │   (б) явный прокси  10.99.77.1:1081 (SOCKS5) / :8081 (HTTP)   — рабочий
   │   (в) всё остальное — прозрачно, через шлюз Windows (см. windows-setup.md)
   ▼
Роутер OpenWrt (VirtualBox) + PassWall2 / Xray
   ├─ ПУЛ (POOL leastPing): узлы подписки, выбор по минимальному пингу, проба раз в минуту — для 1080/8080 и системного трафика
   └─ РАБОЧИЙ ВЫХОД (USA-via-pool): ПЕРВЫЙ ХОП (POOL chain) ──► ваш сервер (VLESS+Reality) — выход с вашим IP
```
Название узла `USA-via-pool` условное: ваш сервер может быть в любой стране. «Пул → ваш сервер» означает цепочку: соединение сначала идёт на самый быстрый узел из **пула первого хопа** (`POOL chain`), а оттуда на ваш сервер (так он достижим, даже если напрямую до него не добраться).

## 2. Порты и пути трафика
| Путь | Кто так ходит | Узел с правилами | Выход |
|---|---|---|---|
| `10.99.77.1:1080` (SOCKS5) / `:8080` (HTTP) | программы, где вы указали этот прокси | `shunt_pool` | пул; RU и CN напрямую, UA блок |
| `10.99.77.1:1081` / `:8081` | рабочие программы (браузер, редактор, терминал) | `shunt_usa` | ваш сервер через пул; RU и UA блок; при отказе — запасной узел |
| прозрачный шлюз Windows | любая программа без своего прокси | `shunt_pool` (`SYSTEM_MODE=same`) | как 1080/8080 |
| трафик самого роутера (opkg, пробы) | роутер | — | напрямую |

Подробности правил — [routing-rules.md](routing-rules.md).

## 3. Узлы PassWall2 (`/etc/config/passwall2`)
- Группа **подписки** (`subscription`): узлы провайдера. Провайдеры периодически меняют адреса и идентификаторы узлов.
- Группа **`own`**: `USA-via-pool` (ваш рабочий сервер, `chain_proxy=1`, `preproxy_node=pool_chain`), необязательный дополнительный узел из `LINK_EXTRA`, `POOL leastPing` (`pool_ping`, `_balancing`, стратегия `leastPing`) и `POOL chain (first hop)` (`pool_chain`, те же узлы плюс исключённые из прокси), а также «shunt»-узлы с правилами: `SHUNT pool`, `SHUNT USA`, `SHUNT USA backup`.
- **Shunt-узел** — это узел с правилами: у каждого правила (UA/RU/CN) своё действие: напрямую, блок, «как остальное» или конкретный узел; «остальное» уходит на `default_node`.

## 4. Два переключателя PassWall2 (не путать)
| В LuCI | UCI | Что делает |
|---|---|---|
| Basic Settings → **Main switch** | `global.enabled` | прозрачный прокси для клиентов LAN (nftables: TCP → REDIRECT, UDP → TPROXY на `global.node`) |
| Socks Config → **Main switch** | `global.socks_enabled` | отдельные порты 1080/1081/8080/8081 |

Включены оба. `localhost_proxy=0`: собственный трафик роутера идёт напрямую (иначе возможны петли с пробами и `opkg`).

## 5. Подписка и пул (`pw2-pool-sync`)
Каждые 6 часов (cron `17 */6 * * *`; лог `/root/pw2-pool-sync.log`) скрипт: скачивает подписку → пересобирает список узлов пула **по правилам** `/etc/pw2-pool.conf` → при изменениях перезапускает PassWall2 → обновляет запасной рабочий узел. Нужен потому, что после обновления подписки идентификаторы узлов меняются, а встроенный механизм PassWall2 не добавляет новые узлы в балансировщик.

`/etc/pw2-pool.conf` (меняйте здесь, скрипт трогать не нужно):
| Параметр | Смысл |
|---|---|
| `SUB_SECTIONS` | секции подписок для обновления |
| `INCLUDE_GROUPS` | группа узлов подписки, которые входят в пул |
| `EXCLUDE_REGEX` | какие узлы **не** брать ни в один пул (по умолчанию `USA` — такие узлы резервируются как запасной рабочий выход) |
| `EXCLUDE_FROM_PROXY_REGEX` | узлы, которые **не** используются как выход 1080/8080 и системного трафика (убираются из `pool_ping`), но остаются **первым хопом цепочки** (`pool_chain`). По умолчанию пусто. Пример: `Russia` — если с российского выхода плохо работает, например, видео, а до вашего сервера через него быстро (проверка — [troubleshooting.md](troubleshooting.md), «Какой узел брать первым хопом») |
| `EXTRA_REMARKS` | ваш дополнительный узел из `LINK_EXTRA` (по имени) |
| `MIN_NODES` | защита: если в `pool_ping` подходящих узлов меньше — списки не меняются |
| `POOL_NODE`, `POOL_CHAIN_NODE` | имена узлов-балансировщиков (`pool_ping`, `pool_chain`) |

## 6. Отказоустойчивость
- **Пул**: сам выбирает самый быстрый из доступных узлов; недоступные игнорирует.
- **Рабочий выход**: при отказе вашего сервера порт 1081/8081 сам переключается на запасной узел из подписки и возвращается обратно (~20 с) — [routing-rules.md](routing-rules.md), раздел 4.
- **Windows**: если роутер не отвечает, сторож за минуту отключает шлюз и интернет идёт напрямую (fail-open).

## 7. Что где лежит на роутере
| Путь | Назначение |
|---|---|
| `/usr/share/pw2/` | скрипты установки (00…08) и вспомогательные файлы; `pw2-setup` читает их отсюда |
| `/usr/bin/pw2-*` | команды: `pw2-setup`, `pw2-routing-apply`, `pw2-pool-sync`, `pw2-cn-mode`, `pw2-usa-mode`, `pw2-ua-block` |
| `/etc/pw2-routing.conf`, `/etc/pw2-pool.conf` | настройки правил и пула |
| `/root/secrets.env` | ваши данные (подписка, ссылки), права 600 |
| `/etc/init.d/cn-watch`, `/etc/init.d/ua-block` | службы: сторож Китая, файрвол-блок UA |

Состав сети: LAN роутера `eth0 / br-lan = 10.99.77.1/24` (отдельный Host-Only адаптер VirtualBox, Windows — `10.99.77.2`; DHCP-пул `.100–.199`), WAN `eth1` = мост на ваш сетевой адаптер (DHCP). Подсеть `10.99.77.0/24` выбрана редкой, чтобы не пересекаться с чужими Wi-Fi и корпоративными сетями.
