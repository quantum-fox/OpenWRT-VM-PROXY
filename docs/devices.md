# Подключение других устройств (ноутбук, телевизор, гость) и выбор выхода для них

Применяется с версии **1.9.0** (прозрачный режим был и раньше, команда `pw2-device` — новая).

## 1. Два способа выйти в интернет через роутер
| Способ | Что нужно на устройстве | Для чего |
|---|---|---|
| **A. Подключили и работает (основной)** | ничего: сетевой кабель или Wi-Fi-точка в сети роутера, адрес и DNS выдаёт роутер | любые устройства: ноутбук гостя, телевизор, телефон, умная техника, игры; программы, которые не умеют прокси |
| **B. Прокси** | адрес прокси в настройках программы: `10.99.77.1:1080` (SOCKS, пул) / `8080` (HTTP, пул) / `1081`, `8081` (рабочий выход) | рабочий браузер, программы, которым нужен именно рабочий выход (ваш сервер); работают независимо от способа A |

При способе A весь трафик устройства прозрачно проходит через Xray по тем же правилам, что и у Windows-шлюза: российские и китайские сайты напрямую, украинские блокируются, реклама блокируется, остальное через пул. **Рабочий выход (1081/8081) всегда доступен как прокси и не зависит от способа A**: если прозрачный режим сломается или будет выключен, вы можете работать через прокси.

## 2. Как подключить физическое устройство к сети роутера
LAN роутера — это сеть `10.99.77.0/24` (адрес роутера `10.99.77.1`, DHCP выдаёт `10.99.77.100–199`). Устройство должно оказаться в этой сети, то есть физически или через мост подключиться к сетевой карте VM, которая входит в LAN.

### 2.1. Proxmox (рекомендуется)
Проводной порт сервера — в отдельный мост, а мост — первой сетевой картой VM (ещё один порт позже: `pw2-lan add ПОРТ`) (`net0` = `eth0` роутера = LAN):
```
auto vmbr2
iface vmbr2 inet manual
    bridge-ports ИМЯ_ФИЗИЧЕСКОГО_ПОРТА
    bridge-stp off
    bridge-fd 0
```
(имя порта: `ip -br link`; копию `/etc/network/interfaces` перед правкой сделайте; применить `ifreload -a`; VM: `qm set <id> --net0 virtio,bridge=vmbr2`.) К этому порту подключайте устройства напрямую, через свитч или Wi-Fi-точку в режиме моста. Мост **без** физического порта (`bridge-ports none`) годится, только если клиенты — виртуальные машины этого же сервера. В сегменте не должно быть второго DHCP-сервера (домашний роутер в этот порт не включайте).

### 2.2. VirtualBox на Windows
LAN роутера здесь — виртуальная сеть Host-Only: видна только этому компьютеру. Чтобы подключить другое устройство, нужна **третья** сетевая карта VM на проводной адаптер компьютера, которая входит в LAN роутера. Это делает один скрипт (PowerShell от администратора, папка `tools\windows`):
```
.\lan-port.ps1
```
Скрипт сам находит подключённый проводной адаптер (или укажите `-Adapter "<InterfaceDescription из Get-NetAdapter>"`), выключает сторожа, останавливает роутер, добавляет VM карту-мост, запускает роутер, выполняет в нём `pw2-lan add eth2` и проверяет результат; при неудаче возвращает прежние параметры VM. Простой ~1–2 минуты (у Windows сработает fail-open). Порт становится **отдельной сетью роутера** `10.99.88.0/24` (роутер `10.99.88.1`, DHCP `10.99.88.100–199`): любое устройство, подключённое кабелем к этому порту (напрямую или через свитч), получает адрес по DHCP, шлюз и DNS `10.99.88.1` и выходит в интернет через прокси без настройки. Устройства основной сети (`10.99.77.0/24`) и порта видят друг друга.
- Устройства со **статическими** адресами (например `192.168.100.x`, шлюз `192.168.100.1`): `.\lan-port.ps1 -Address 192.168.100.1/24` даст роутеру этот адрес в сети порта (DHCP на порту при этом выключен), и устройства заработают без перенастройки. Проверено: устройство на таком порту вышло в интернет через пул, как и 1080.
- Убрать порт: `.\lan-port.ps1 -Remove`.
- Ограничения: только **проводной** адаптер (мост VirtualBox на Wi-Fi не пропускает чужие MAC-адреса); компьютер должен быть включён; в порт нельзя включать сеть со своим DHCP-сервером (домашний роутер). Сам компьютер при этом может выходить в интернет по Wi-Fi: он же даёт роутеру WAN. Порт устроен как отдельный маршрутизируемый интерфейс, а не мост: так мост VirtualBox работает без разрешения чужих MAC-адресов.

## 3. Проверка
1. На подключённом устройстве: адрес из `10.99.77.100–199`, шлюз и DNS `10.99.77.1` (Windows: `ipconfig`).
2. Открыть `https://ifconfig.me`: показан адрес сервера из пула, а не ваш провайдерский.
3. Российский сайт открывается (напрямую), украинский не открывается (блок).
4. На роутере список устройств: `ssh openwrt "cat /tmp/dhcp.leases"`.

## 4. Свой выход для отдельных устройств: `pw2-device`
По умолчанию все устройства идут через пул. Команда меняет это для конкретного устройства, диапазона адресов или целого порта:
```
pw2-device set ИМЯ ИСТОЧНИК РЕЖИМ
pw2-device list
pw2-device del ИМЯ
pw2-device on          # включить выбор выхода по устройствам
pw2-device off         # выключить (правила сохраняются)
```
- **ИСТОЧНИК**: IP (`10.99.77.50`), диапазон (`10.99.77.50-10.99.77.60`), подсеть (`10.99.77.64/28`), MAC (`aa:bb:cc:dd:ee:ff`) или интерфейс `if:eth2` (всё, что подключено к этому порту; несколько источников через запятую).
- **РЕЖИМ**: `pool` — через пул (как у остальных), `work` — через рабочий выход (ваш сервер; российские ресурсы блокируются), `direct` — мимо прокси, напрямую (камеры, умный дом, устройства, которым прокси мешает).

Примеры:
```
pw2-device set tv 10.99.77.50 pool                  # телевизор через пул (и так по умолчанию, но можно закрепить)
pw2-device set work-laptop aa:bb:cc:dd:ee:ff work   # рабочий ноутбук всегда через ваш сервер
pw2-device set cameras 10.99.77.200-10.99.77.220 direct
pw2-device set guests if:eth2 pool                  # весь гостевой порт через пул
```
Замечания:
- После команды PassWall2 перезапускается, правило начинает действовать через ~30 секунд.
- Устройству лучше закрепить адрес (резервирование в DHCP роутера: LuCI → Network → DHCP and DNS → Static Leases), иначе правило по IP «потеряет» его после смены адреса; по MAC-адресу правило остаётся верным, но у телефонов с «случайным MAC» MAC может меняться.
- Каждое правило `pool`/`work` запускает отдельный процесс Xray (около 50 МБ при полной базе рекламы): для двух и более таких правил выделите VM 512 МБ ОЗУ (`vm-tune.ps1 -MemMB 512`). Правило `direct` процесса не требует.
- Проверено на живом роутере: одно и то же устройство в режимах `pool`, `work` и `direct` вышло через три разных внешних адреса.

## 5. Если прокси или роутер упали
Прозрачный режим **не возвращает трафик мимо прокси сам**: если Xray или PassWall2 остановлены, устройства теряют интернет (так сделано намеренно, чтобы трафик не утёк мимо прокси). Что делать:
- Рабочий выход: настроенные на прокси программы тоже перестанут работать, пока не поднимется Xray; смотрите `ssh openwrt pw2-setup status` и `ssh openwrt "/etc/init.d/passwall2 restart"`.
- Временно отдать устройствам прямой интернет без прокси: в LuCI PassWall 2 → Basic Settings → **Main switch** выключить (порты 1080/8080 при этом остаются). Включить обратно, когда всё починено.
- Для Windows-шлюза есть сторож с автоматическим отключением шлюза; для других устройств автоматического обхода нет.
