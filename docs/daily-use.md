# После установки: как это работает каждый день

Вы собрали роутер ([вариант A](../A-from-scratch/README.md) или [B](../B-ready-image/README.md)) и подключили Windows ([windows-setup.md](windows-setup.md)). Что дальше — здесь.

## 1. Главное
- **Локальная программа для VLESS не нужна.** Роутер (виртуальная машина `OpenWRT` в VirtualBox) сам скачивает вашу подписку, выбирает лучший узел и подключается к вашему серверу. На Windows не должны работать v2rayN, Throne, Clash, Outline и другие VPN/TUN-клиенты — они только мешают шлюзу (см. [windows-setup.md](windows-setup.md), шаг 4).
- **Всё запускается само.** При входе в Windows сторож (задача `OpenWRT-Gateway-Watchdog`) запускает VM без окна и включает шлюз. Окно VirtualBox открывать не нужно.
- **Подписка и пул обновляются сами** каждые 6 часов. Ничего регулярно делать не требуется.

## 2. Что происходит после включения компьютера
1. Вход в Windows → сторож запускает VM `OpenWRT` (если она не запущена).
2. Роутер загружается ~30 с, ещё ~20 с стартует PassWall2.
3. Сторож включает шлюз: весь трафик Windows пойдёт через роутер (если вы один раз выполнили `gateway-on` — [windows-setup.md](windows-setup.md), шаг 6; после этого шлюз поддерживается автоматически).

Первые **2–4 минуты** после входа интернет идёт напрямую (шлюз ещё не включён) — это нормально. Если роутер перестанет отвечать, сторож за минуту отключит шлюз и интернет вернётся напрямую (fail-open); когда роутер оживёт, шлюз включится снова. После сна или смены Wi-Fi состояние восстанавливается за минуту.

## 3. Что куда идёт
| Что вы делаете | Как идёт трафик | Откуда вы «выходите» |
|---|---|---|
| Обычные программы и браузеры **без настроек** | автоматически через шлюз | узел пула с лучшим пингом (страна и IP **меняются** со временем). Российские и китайские сайты — напрямую, украинские блокируются |
| **Рабочий браузер** (отдельный профиль, настроен на порт `1081`) | явный прокси `10.99.77.1:1081` | **только ваш сервер**: постоянный IP и страна сервера. Российские и украинские сайты в нём блокируются намеренно |
| VS Code и терминал (если включили `vscode-proxy.ps1`) | прокси `10.99.77.1:8081` | ваш сервер, как у рабочего браузера |
| Программа, где вы вручную указали `10.99.77.1:1080` / `:8080` | явный прокси | пул, как у обычных программ |

### Рабочий браузер: его нужно настроить один раз
Автоматически через ваш сервер ходит **только то, что вы явно направили на порт `1081` (SOCKS5) или `8081` (HTTP)**. Остальные браузеры идут через пул — это другая страна и другой IP. Поэтому для работы, где нужен постоянный IP и страна сервера, заведите **отдельный профиль браузера** и настройте его:
- **Firefox** (проверено): скриптом `firefox-proxy.ps1 -ProfileDir "<профиль>" -Port 1081` или вручную — [windows-setup.md](windows-setup.md), шаг 3. Обязательны: SOCKS v5 и галка «Proxy DNS при использовании SOCKS v5».
- **Chrome/Edge** (не проверялось в этом проекте): ярлык отдельного профиля с параметрами `--user-data-dir="%LOCALAPPDATA%\WorkBrowser" --proxy-server="socks5://10.99.77.1:1081"`. Результат проверьте по разделу 5.

Запасной выход: если ваш сервер недоступен, порт `1081/8081` автоматически (~20 с) переключается на узел USA из подписки и возвращается, когда сервер снова работает. Пока включён запасной выход, IP и страна **другие** — как проверить, какой выход сейчас, см. раздел 4.

## 4. Как проверить, что всё работает
Выполняйте сверху вниз, остановитесь на первом шаге, который не прошёл.

| № | Проверка | Ожидание | Если не так |
|---|---|---|---|
| 1 | `VBoxManage list runningvms` (`C:\Program Files\Oracle\VirtualBox\VBoxManage.exe`) | в списке есть `"OpenWRT"` | подождите минуту (сторож запустит); иначе `VBoxManage startvm OpenWRT --type headless` |
| 2 | `Test-Connection 10.99.77.1 -Count 2 -Quiet` | `True` | роутер ещё грузится (до 1–2 мин) |
| 3 | `ssh openwrt pw2-setup status` | узлы подписки в списке; выходы 1080 и 1081 — IP-адреса; `автопереключение 1081: 1`, `cn-watch: running`, `ua_block: 1` | пустой выход — [troubleshooting.md](troubleshooting.md) |
| 4 | `ssh openwrt pw2-usa-mode status` | `ОСНОВНОЙ` (ваш сервер) | `ЗАПАСНОЙ` — ваш сервер сейчас недоступен через пул, работает узел из подписки |
| 5 | `(Get-NetRoute -NextHop 10.99.77.1).DestinationPrefix` | две строки `0.0.0.0/1` и `128.0.0.0/1` | шлюз выключен: `gateway-on.cmd` (подробнее — [windows-setup.md](windows-setup.md), раздел 3) |
| 6 | `Get-Content C:\ProgramData\win-gateway\watchdog.log -Tail 10` | «шлюз включён, интернет проверен» | при «FAIL-OPEN» роутер не отвечал — см. шаги 1–3 |
| 7 | `ssh openwrt "tail -20 /tmp/log/passwall2.log"` | без повторяющихся ошибок | — |

Если интернет пропал совсем: `gateway-off.cmd` (интернет вернётся напрямую), затем разбирайтесь по таблице выше.

## 5. Как убедиться в браузере, что выход в нужной стране
Откройте в **нужном** браузере (рабочем — для рабочего выхода, обычном — для пула) один из адресов:
- `https://icanhazip.com` — только ваш внешний IP;
- `https://ipinfo.io/json` — IP, страна (`country`), город, провайдер (`org`);
- `https://www.cloudflare.com/cdn-cgi/trace` — строки `ip=` и `loc=` (код страны).

Что должно быть:
| Браузер | Ожидаемый результат |
|---|---|
| **Рабочий** (порт 1081) | IP и страна **вашего сервера** — те же, что вы видите в панели вашего VPS. Адрес всегда один и тот же |
| **Обычный** (шлюз) | IP какого-либо узла пула (не вашего сервера); страна и IP могут меняться |
| Любой браузер, **российский сайт** (например `https://yandex.ru`) | открывается напрямую; на сайтах «мой IP» для российских проверок виден ваш реальный провайдер |

Если рабочий браузер показывает **не** ваш сервер:
1. **Ваш реальный IP или IP пула** — в профиле не настроен прокси (Параметры сети: SOCKS-узел `10.99.77.1`, порт `1081`, SOCKS v5). Закройте Firefox и выполните `firefox-proxy.ps1` ещё раз.
2. **Другой IP/страна, один и тот же стабильно** — вероятно, включён запасной выход: `ssh openwrt pw2-usa-mode status`. Проверьте ваш сервер и ссылку `LINK_WORK` в `/root/secrets.env`.
3. **Сайт не открывается** — это может быть сознательная блокировка: в рабочем выходе блокируются российские и украинские сайты ([routing-rules.md](routing-rules.md)).

Проверка из командной строки (без браузера): `curl.exe -x socks5h://10.99.77.1:1081 https://icanhazip.com` — должен вернуть IP вашего сервера; `curl.exe -x socks5h://10.99.77.1:1080 https://icanhazip.com` — IP узла пула. В терминале VS Code с включённым `vscode-proxy.ps1` простой `curl.exe` идёт через рабочий выход; системный путь проверяйте с `--noproxy "*"` ([commands.md](commands.md)).

## 6. Что делать, когда что-то меняется
| Что изменилось | Что сделать |
|---|---|
| Другая подписка или сервер | на роутере: `vi /root/secrets.env` (или `ssh -t openwrt pw2-setup` — спросит заново), затем `pw2-setup apply` |
| Нужно временно отключить шлюз (другой VPN, диагностика) | `gateway-off.cmd`; вернуть — `gateway-on.cmd`. VM можно не выключать |
| Нужно остановить VM совсем | сначала `Disable-ScheduledTask OpenWRT-Gateway-Watchdog` (администратор), потом `ssh openwrt poweroff`; вернуть — `Enable-ScheduledTask OpenWRT-Gateway-Watchdog` |
| Изменить правила по странам, пороги, пул | [routing-rules.md](routing-rules.md), раздел 5 (шпаргалка) |
| Обновить скрипты из новой версии продукта | `install-router.ps1`, затем `ssh openwrt pw2-setup apply` |
| Выйти из схемы совсем | [windows-setup.md](windows-setup.md), раздел 4 «Полный откат» |

Все команды роутера и Windows — в [commands.md](commands.md); неполадки — в [troubleshooting.md](troubleshooting.md).
